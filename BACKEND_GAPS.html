3. 🆕 Endpoints adicionados desde 29/05

POST /v1/paciente-app/auth/esqueci-senha P0 RESOLVIDO
Implementado Aceita { cpf }. Retorna sempre 204 (anti-enumeration). Rate limit: 3 tentativas/h por CPF+IP. Token TTL 30min, uso único, escrito em paciente_recovery_tokens. Email enviado via SMTP se a conta tem email cadastrado.
POST /v1/paciente-app/auth/redefinir-senha P0 RESOLVIDO
Implementado Aceita { token, novaSenha }. Validações: token existe + não expirou + não foi usado. Marca usadoEm = now() ao usar (single-use).
POST /v1/paciente-app/auth/registrar-dispositivo P1 RESOLVIDO
Implementado Aceita { endpoint, plataforma, appVersion? }. Provider NTFY é default (FCM disponível como alternativa). UPSERT em paciente_dispositivos. Aliases para compatibilidade: /push-token, /fcm-token.

6. 🔍 Falsos-positivos do doc anterior

Durante a re-auditoria, 2 itens descritos como "gaps reais" se mostraram falso-positivos. Documentados aqui para evitar repetir confusão futura.

⚠ Falso-positivo · TFD payload

Doc anterior alegou: app envia { encaminhamentoId, motivoConsulta } sem prioridade, esperando que o backend derive.

Realidade auditada: o app envia { viagemId, justificativa, encaminhamentoId?, acompanhante? } e o backend já espera exatamente esse shape em criarTfdSolicSchema. A prioridade é derivada no servidor (sem encaminhamento → NORMAL; com encaminhamento → PRIORITARIA ou URGENTE conforme severidade). 

// app envia (data/repositories/tfd_repository.dart)
{
  'viagemId': viagemId,
  if (encaminhamentoId != null) 'encaminhamentoId': encaminhamentoId,
  'justificativa': justificativa,
  if (acompanhante != null) 'acompanhante': acompanhante,
}

// backend valida (PacienteAppController.ts:109)
const criarTfdSolicSchema = z.object({
  viagemId:         z.string().min(1),
  justificativa:    z.string().min(10),
  encaminhamentoId: z.string().optional(),
  acompanhante:     z.string().optional(),
});

⚠ Falso-positivo · Notificações.mensagem

Suspeita inicial: app esperaria campo mensagem mas backend envia corpo.

Realidade auditada: o modelo Dart do app já lê corpo diretamente, sem adapter. Não há divergência.
