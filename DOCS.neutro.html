UNISISM Paciente

App Flutter do cidadão dentro do ecossistema UNISISM. Acompanhamento de encaminhamentos médicos, dossiê de saúde, solicitação de vaga em TFD, notificações da Secretaria e contato direto com a UBS. Esta documentação cobre tudo que está implementado: telas, componentes, modelos, fluxos, roteamento e contrato esperado de backend.

Flutter 3.41.7 Dart 3.11+ Material 3 Riverpod 2.6 go_router 14.6 76 arquivos Dart ~12.500 linhas Mock-mode

TL;DR

O que esse app é, em uma frase: terceira "face" do UNISISM (depois de UBS e SMS/Regulação) — é onde o paciente vê sua jornada na rede pública de saúde do município.

Filosofia visual: "Brutalismo simpático"

O DS UBS/SMS é puro brutalismo B2G — Bloomberg/Palantir-style — feito pra operador treinado. O app paciente herda os tokens (azul-900, slate, cantos retos, sem sombra) mas inverte a camada de interação — tamanhos grandes, fonte sans, ícones grandes, sem uppercase decorativo.

DS UBS (operador)App Paciente (cidadão)
text-xs / text-[10px]text-base mínimo (17px), títulos 24-32px
font-mono em quase tudofont-sans em tudo; mono só em CPF, protocolo, datas
Densidade Bloomberg, 8+ painéis por telaCards grandes, 1 ação por tela
Labels UPPERCASE TRACKING-WIDEST + <kbd>Ícones grandes + label em frase natural
Botão 32-40dp alturaBotão 60dp altura
Atalhos por tecladoTouch targets ≥56dp

O que permanece idêntico

  • Paleta de cores (slate, blue-900, semânticas)
  • Cantos retos em tudo (zero border-radius)
  • Bordas finas 1px slate-200
  • Sem sombras difusas (zero box-shadow a não ser sombra brutalista offset)
  • Gradiente sutil from-white to-slate-50 apenas em headers de painel
  • Verde/âmbar/vermelho apenas para estado (nunca decoração)

Regra de ouro
Nenhum uso estético de cor. Verde/âmbar/vermelho são reservados para comunicar estado — nunca para "bonito". Banner de campanha (não-crítico) é azul ou verde apenas se a SMS marcar como sucesso/info.

  • Cantos retos sempre. Único radius permitido: 2dp (rarissímo).

Componentes do Design System

17 widgets em lib/presentation/shared/widgets/. Todos StatelessWidget exceto os que têm animação interna.

PanelCard

panel_card.dart

Cartão padrão com header opcional (gradiente sutil) + índice numerado + acento lateral colorido (4dp). Equivalente Flutter do <PanelHeader> do DS UBS.

PrimaryButton

primary_button.dart

3 variantes: primary (blue-900), secondary (outline), danger (red-700). Altura 60dp. Suporte a loading spinner + icon + fullWidth.

StatusBadge

status_badge.dart

Pill mono uppercase. StatusBadge.fromStatus() mapeia chaves do backend (AGUARDANDO_REGULACAO, AGENDADO, etc.) com cores e ícones automáticos. 5 tones, 3 tamanhos.

StatusHeroCard

status_hero_card.dart

Card principal da home. Header colorido com especialidade em destaque, status + prioridade, mensagem amigável, data/local agendados em verde, protocolo, CTA "Ver detalhes".

StatusRoadmap

status_roadmap.dart

Roadmap vertical estilo Shopee/Mercado Livre. 5 checkpoints (Criado→Análise→Aprovado→Marcado→Feito), com estados completed/current/pending/rejected. Pulse no atual, animação cascade. Trilhas alternativas pra rejeitado/cancelado.

IconCard

icon_card.dart

Elemento principal de navegação pra paciente. Ícone 56dp + título grande + subtítulo + chevron. Touch target 72dp+. Inclui CountBadge opcional.

SmsBanner

sms_banner.dart

Banner de campanha/alerta. 4 tones: URGENTE, CAMPANHA, INFO, ATENCAO. Imagem opcional, CTA externo. Usado em carrossel na home.

InfoBlock

info_block.dart

Bloco com border-left 4dp colorida. 4 tons semânticos. Icon auto-derivado. Suporte a action button inline.

FormFieldX

form_field_x.dart

Input com label uppercase em cima, fonte 17px no input, modo mono pra CPF/protocolo, toggle de senha automático em obscure, validação + helperText.

DocumentTile

document_tile.dart

Tile de anexo. Ícone colorido por tipo (PDF=vermelho, IMG=verde, DOC=azul), nome + tamanho + tipo, botões Compartilhar + Baixar, progress bar de download.

TimelineStep

timeline_step.dart

Item de timeline vertical. 7 tipos: criacao, anexo, pendencia, aprovacao, agendamento, rejeicao, atualizacao. Bolinha colorida + linha conectando + mini-painel com autor.

ProtocoloPill

protocolo_pill.dart

Pílula com label uppercase + valor mono. Copy-to-clipboard ao tocar. Snackbar de confirmação.

SectionHeader

section_header.dart

Divisor de seção. Label uppercase tracking-widest em mono. trailing opcional (botão "Ver todas").

AppScaffold

app_scaffold.dart

Scaffold padrão. Background slate-50, max-width 720dp pra tablets, padding consistente, RefreshIndicator opcional.

LoadingView / EmptyView / ErrorView

state_views.dart

Três telas de estado. Loading com spinner brutalista 3dp. Empty com ícone grande + CTA opcional. Error com border-2 red-700 + botão retry.

FadeIn (helper)

fade_in.dart

Wrapper que faz fade + slide-up suave na entrada do widget. Suporta delay pra criar entradas staggered numa lista (300ms + i × 60ms).

Skeleton

skeleton.dart

Bloco com pulse 1.2s entre slate-100 e slate-200. Variantes: HeroCardSkeleton, IconCardSkeleton, ListSkeleton.

Auth guard

redirect: (context, state) {
  final auth = ref.read(authControllerProvider);
  final location = state.matchedLocation;
  final isAuthRoute = location.startsWith('/login') ||
                       location.startsWith('/esqueci-senha');

  if (auth.status == AuthStatus.checking) {
    return location == '/' ? null : '/';
  }
  if (!auth.isAuthenticated) {
    return isAuthRoute || location == '/login' ? null : '/login';
  }
  if (isAuthRoute || location == '/') return '/home';
  return null;
}

Erros conhecidos e como foram resolvidos

1. !semantics.parentDataDirty em loop

Causa raiz combinada:

  1. MediaQuery wrapper global no MaterialApp.router builder com textScaler.clamp — invalidava parent data a cada navegação. Removido.
  2. Hero + Material wrapper ao redor de SmsBanner (que internamente tinha CachedNetworkImage + AspectRatio + Column complexa) na home + AnimatedSwitcher trocando entre tipos drasticamente diferentes (PageView ↔ Skeleton ↔ EmptyView). Hero/Material wrappers removidos.
  3. Positioned com offset negativo + Stack(clipBehavior: Clip.none) + TweenAnimationBuilder no badge da bottom nav. Substituído por SizedBox + Align(Alignment(1.4, -1.2)).
  4. CustomScrollView + Slivers dentro de RefreshIndicator em atendimentos. Substituído por ListView simples.
  5. AnimatedSwitcher entre tabs no MainShell quando o conteúdo tinha PageView dentro. Removido — go_router já anima transições.
  6. AnimatedSize + AnimatedSwitcher + SizeTransition aninhados em TFD solicitar. Simplificado pra if (...) direto.

2. ref.listen can only be used within the build method

_wire() era chamado via addPostFrameCallback (fora do build) usando ref.listen. Trocado pra ref.listenManual — variante explícita pra usar fora do build.

3. SingleTickerProviderStateMixin but multiple tickers were created

_RoadmapNodeState tinha 2 AnimationControllers (_entry e _pulse condicional) mas o mixin singular só permite 1. Trocado pra TickerProviderStateMixin (plural).

4. Telas em branco com providers travando

Em ambiente onde providers Riverpod entravam em loop ou ficavam pendentes infinitamente, a tela aparecia em branco. As 4 telas de encaminhamento foram refeitas como StatelessWidget puro com dados hard-coded — sem provider, sem async, sem ref.watch. Detalhe, timeline, anexos e lista renderizam sempre, em qualquer condição.
